# W16 首次安装启动计时

范围：`taro/main` 基线 `3a7ba16`，仅加入计时，未改启动顺序、迁移、同步或持久化行为。计时数据只在 `TARO_PERF_OVERLAY=1` 预览构建里收集；普通构建的计时封装直接执行原操作。

## 出厂库与版本戳

`wechat-miniprogram/scripts/upload-cloud-content.sh` 上传的数据库源文件是 `frontend/public/nihongo.db`，同时用 `gzip -9 -c` 生成 `seed/nihongo.db.gz`。本次测量的出厂库为 11,567,104 B，SHA-256 `363d9d908a97d46a1d8fb406cc3723091982e7379f165167dcd73bc0a68120e1`；gzip 为 2,193,012 B，解压后与该文件相同。

数据库里的 JLPT 种子、词条元数据、振假名、词级别覆盖、补充词典和语法版本，与代码常量一致；语法库为 769 条。`content_marker_repair`、`jlpt_collocation_content_version` 和 `kana_reading_fix_version` 标记在这份库中缺失。

这些缺失标记**不是 Taro 首次打开的已证实根因**：当前 Taro 首页调用 `ensureDatabase`、`ensureUserTables`、`ensureSyncSchema`、`getProgressOverview`，不调用网页的 `ensureSeedData`，因此也不会运行它包含的内容迁移。Taro 首次首页实际会补 10,919 条单词进度与 769 条语法进度，并做 schema 检查。汉字卡和辨析卡物化在后续学习/备考入口，不在 Taro 首页首启路径。

## 最大阶段与可讨论方向

1. **同步结构：149 ms，940 条 SQL。** 可由 Claude 评估新库建表与现有库校验是否能避免重复检查。风险：漏掉同步列、触发器或删除墓碑会静默破坏跨设备合并；本分支不改。
2. **单词进度初始化：65 ms，补齐 10,919 行；被 76 ms 的首页数据计算包含。** 可评估新种子是否预置空进度行、或首页是否能先显示后补齐。风险：占位行若盖同步时间戳会覆盖用户真实进度；显示过早也可能暂时呈现错误的已学/待复习数。
3. **主页内容包：21 ms（Node 同步 fallback）。** 可用 iPhone 真机结果判断是否要拆分首页阻塞的内容加载。风险：过度延后会让首张题卡缺题面或读音数据；本数字不能代表微信异步分包时长。

Node 的三项是一次模拟值，DevTools 的首帧值来自一次已有本机库运行。真机三次冷启动和清数据首次安装截图尚缺；云端下载时间也只能由设备测得。需要扫码测试后再据真机三次稳定值和首次安装值决定是否优化。
