# 第一次使用的引导 —— 制作理念与内容清单

> 状态：**设计稿，未实现**（2026-09-05）。仓库里目前没有任何引导代码。
> 这份文档的用途是：等真做的时候，不用重新做一遍下面这些取舍。

---

## 0. 现在第一次打开是什么样（现状盘点）

| 事实 | 代码位置 |
|---|---|
| 没有任何首次引导 | `grep -i "onboard\|tutorial\|首次\|新手"` 在 src 下只命中 `HelpPage.tsx` 的一个折叠块 |
| 唯一的教程是「我的 → 帮助和支持 → 使用教程」里三条文字，**被动、藏三层深** | `pages/HelpPage.tsx:63` |
| 默认偏好：每天 15 个新词、目标 N3、复习上限自动、经典模式 | `lib/studyPreferences.ts:66` 的 `defaultStudyPreferences` |
| 打开首页就给全库 11,740 个词建 progress 行 | `word-api/bootstrap.ts:24` `ensureProgressInitialized` |
| **第一场的 15 个新词是从 N3 及以下随机抽的** | `word-api/stage1.ts:153` 的新词 SQL + `word-api/filters.ts:133` `newWordOrderSql` |
| 免费用户不撞付费墙（锁的只有沉浸语法 / 高级统计 / 无限错题本 / 完整 JLPT 规划） | `lib/entitlements.ts` |

**一句话概括现状**：新用户从下载到答第一张卡，**一个决定都没做过**，包括「学什么词」。

## 1. 制作理念（七条，每条都有判据）

### ① 不做产品导览

实测数据一边倒：产品导览 5 步以上放弃率 63%、10 步以上 81%；静态 tooltip 平均 79.4% 被直接划掉，
真去看的人平均只停 2.1 秒——**超过 15 个字就读不完**。NN/G 的结论更直接：引导教程「被严重滥用」，
根因是「主动用户悖论」（paradox of the active user）：人打开 App 是想马上用，不是想先上课。

所以：**开场不介绍任何功能**。动物园、温泉、成就、疑难辨析、一字多音、六格工具、查词汇量，
一个都不在第一次打开时出现。

### ② 唯一目标是 60 秒内翻到第一张卡

「aha moment」在这个 App 里不是界面好看，是**翻面那一下**：他看到自己认不认得，
以及按完「忘记」之后发现这个词今天真的又回来了。整个引导只服务这一件事，
任何一步如果不能把他往「第一次翻面」推进，就砍掉。

### ③ 引导 = 替他做完非做不可的决定，不是介绍功能

第一场开始前**只有三个决定绕不过去**：

1. 今天学什么词（现在是替他随机选的 → 见第 2 节，这是要改的）
2. 一天学几个（现在默认 15）
3. 目标等级（现在默认 N3，只影响备考卡和混合模式的语法等级，可以最后问）

其余全部延后：主题、音效、动效、声音、罗马音、复习上限、云同步、通知——
**没有一个会让第一场学不下去**。

### ④ 其余的靠上下文触发，不在开场讲

行为触发的引导比静态导览高 2.5×（58.7% vs 23.7%）参与率，按需出现的提示让功能采用率高 2.9×。
这个 App 里天然的触发点很多：第一次答错、第一次看到拍数标签、第一次学完一天、第一次没新词了。
**在他撞上那件事的那一刻说一句**，比开场讲十句管用。

### ⑤ 一切可跳过、可重看，且跳过之后仍然走得通

跳过 = 用默认值继续，不是死路。「可重看」的落点只有一个：`HelpPage` 那个折叠块
（把它改写成和引导同一份内容）。**别再建第二处说明**——这个 App 已经在辨析、词形、
学习时长上吃过「同一件事两份口径」的亏。

### ⑥ 不承诺算法，只承诺行为

SRS 对新手的三个真困惑，全是「会发生什么」不是「算法是什么」：

- 我点了「忘记」会怎样？（→ 今天还会回来两三次）
- 昨天学过的今天为什么又来了？（→ 就是要在快忘的时候再问一次）
- 为什么今天只有这么点？（→ 剩下的排在后面几天，学不完不会丢）

**一个字都不要提 FSRS、稳定性、难度、间隔。** 那些放 HelpPage。

### ⑦ 权限和账号一律延后

通知权限在开场问几乎必被拒；正确时机是他**第一次学完一整天之后**。
账号更是——这个 App 本身完全离线可用，第一次打开就要注册是最大的一道墙。
`AuthDialog` 现有的入口已经够了。

## 2. 不自动填词（用户明确要求的那条）

### 现状

新词来源是「全库 `seen_count = 0` 的词，N3 及以下同档随机」（`filters.ts:133`）。
所以第一次打开首页，大卡上就已经躺着 15 个他没见过、也没同意过的词。

### 为什么这条值得改（不是洁癖）

**学习一侧**：自选 / 自建词表带来更深的加工和更高的自主性，这在数字卡片的研究里是站得住的。
⚠️ 但注意那些研究说的是「自己**造**卡」，不完全等于「自己**勾**词」——
文案里别过度承诺「自己选的记得更牢」，说「先学你想学的」就够了。

**产品一侧**：第一场的词是「我挑的」，放弃成本完全不同。而且**这个 App 已经有整套挑词设施**
（词库页的批量勾选 + `addWordsToQueue` + `dictionary_discovered_words` 的最高优先级），
引导只是把它摆到第一次打开的必经之路上，**不需要新建任何通道**。

**口径一侧**：`filters.ts` 那段注释自己写着「用户在别处学过，低级别词大多本来就会，
排在前面等于逼他把会的重刷一遍——靠答题分辨比靠级别猜准」。这话在**第 100 天**成立，
因为那时算法有他的作答数据。**第 1 天他一张卡都没答过，随机就是纯噪音**。

### 怎么落（三档，按懒程度排）

**A（推荐，最懒）：引导最后一屏给三条路，不给「随便给我」**

1. **自己挑** → 跳词库页，勾完回来（词库页的整批勾选：全选 / 未学 / 该复习 / 顽固 / 清空，已经有了）
2. **先测一下** → 跳查词汇量，测完按结果落到某个等级范围再挑
3. **就按 N5 给我排** → 明示的默认，写清楚是 N5 不是「随便」

⚠️ **不给第四条「随便给我一批」**——那正是现在的行为，等于这一屏白做。

**B：加一个偏好 `autoFillNewWords`（默认 false）**

`stage1.ts` 的新词 SQL 在 false 时只取前两档（`dictionary_discovered_words` + carried），
不落到全新词那一档。A 是第一天的路，B 是第 30 天他把挑的词学完之后**不被偷偷塞词**的保证。

**C：真正的「自己造卡」（自己输入词和释义）—— 不做。** YAGNI，而且词库已经有 11,740 个词。

**建议 A + B 一起做。** A 单独做的话，第二天算法照样开始随机填词，用户会觉得被骗了一次。

### ⚠️ 落地时的坑（都是从已知口径推出来的，别现踩）

- **必须走 `addWordsToQueue`**，它只收未学的词、额度之外的自动进 `dictionary_discovered_words`，
  天然满足「今天先给我挑的这些」。别新写一条通道。
- **一次上限 300**（和词库页「全选」同一个数）。引导里别放开这个限制。
- **绝对不能走 `focus: "picked"` 自选清单**：那条是 `transient`、不进今日计划、不进 FSRS 队列。
  拿它做第一次学习的话，第二天那批词会全部消失，用户的第一天等于白学。
- **队列空了不能变成死路**：`dailyNewQuota` 拿不到词时，首页大卡必须写「今天没有新词了，
  去挑几个」并给入口，否则第 N 天打开是一张空卡（`ZooHome` 现在的空态文案是
  「今天的路走完了」，那句在这个场景下是错的）。
- 引导里勾完词要 `resetConfusionGroups()` + `resetFamiliarityCache()`？
  **不用**——那两条是给「导入新词单」用的，勾选不改词表本身。

## 3. 具体要提示什么（内容清单）

分三层。**层与层之间不许互相搬运内容**——同一句话说两遍就是噪音。

### A 层：开场（≤3 屏，目标 60 秒内翻到第一张卡）

| 屏 | 说什么 | 为什么是它 | 跳过后的默认 |
|---|---|---|---|
| 1 · 欢迎 | 松鼠 + 一句定位：「一天十几个词，什么时候该复习交给算法排」 | 全流程唯一一屏纯品牌，也是唯一允许的「介绍」 | — |
| 2 · 你现在什么水平 | 三个按钮：零基础 / 学过一点 / 学过不少（第三个建议先查词汇量） | 自分段，Duolingo 那套的核心；分完段第 3 屏的推荐范围才有依据 | N5 |
| 3 · **挑今天学什么** | 见第 2 节的三条路 | 用户要的那条 | 这一屏**不给静默跳过**，但「就按 N5 给我排」是明示的出口 |

**「一天学几个」不单开一屏**：放在第 3 屏挑完词之后的一行滑杆，默认 15，旁边写「随时能在设置里改」。
理由——这是个能反悔的设置，占一整屏不值，而且和「挑词」是同一个动作的两半。

**「目标等级」也不单开一屏**：第 2 屏的自分段已经隐含了。真要问，放第一天学完之后。

### B 层：第一场之内的上下文提示（各只出现一次，不是模态框）

按触发时机排。每条**一句话、不超过 20 个字**（tooltip 平均只被看 2.1 秒）。

| 触发 | 提示 | 为什么非说不可 |
|---|---|---|
| 第一张卡出现、还没翻面 | 「先自己想一下，点一下看答案」 | 「点哪都能翻」这件事不明显；而且现在**按任意键就会翻面** |
| **第一次翻面** | 四颗按钮下方一行：「按刚才的真实感觉选，它决定这个词下次什么时候回来」 | ⚠️ **这是整个 App 唯一真正需要教的东西**。选错档 = 给 FSRS 喂假数据，后面全歪 |
| 第一次点「忘记」 | 「它今天还会回来两三次」 | 新手最怕点忘记（像认输）；不说清就会为了好看按「认识」 |
| 第一次点「熟知」 | 「这个词会排到很久以后」 | 反向的同一件事，防止随手乱按 |
| 第一次看到拍数标签 | 「这行中文可能对得上好几个词，拍数帮你确认在问哪个」 | 「4拍」这个标签凭空出现，不解释会被当成难度分 |
| 第一次学完当天全部 | 完成页一行：「明天会自动排好，包括今天答错的那些」 | 这是决定他明天回不回来的那句话 |

⚠️ **六条是上限不是清单。** 真上线先只做前三条（出现 / 翻面 / 忘记），
剩下三条等真有人问了再补。这个 App 的「模糊」占到 25-30%，
而 `word-study-utils.ts` 里已经写着「说明书只在第一次有用，分量要靠尺寸说」——
**四颗按钮的那份说明书，本来就该属于这一层，而不是常驻卡面**。

### C 层：第一天之后（严格说不算 onboarding，但属于「第一次使用」）

| 时机 | 说什么 |
|---|---|
| 第 2 天首次打开 | 「昨天学的 12 个里有 8 个今天要复习——忘掉再想起来才记得住」 |
| 第一次「今天没新词了」 | 给挑词入口（配合第 2 节的 B 档） |
| 第 1 天完成页之后 | **这时才**问通知权限 |
| 连着用满 3 天 | **这时才**提云同步 / 登录 |
| 一直不提 | Pro。免费档已经能完整学下去 |

## 4. 明确不做的（写下来，免得下次重新讨论）

- ❌ 产品导览 / 逐个功能高亮气泡
- ❌ 「你为什么学日语」这类**不改变任何行为**的问卷（改变不了排词，就是纯摩擦）
- ❌ 开场要账号、开场要通知、开场推 Pro
- ❌ 任何不可跳过的模态；视频 / 动图教学
- ❌ 在开场解释 FSRS、稳定性、间隔、顽固词、辨析、动物园
- ❌ 「随便给我一批词」按钮（见第 2 节）

---

## 5. 怎么算做成了

只需要两个数，其余先不埋：

1. **多少人翻到了第一张卡**（引导本身有没有把人送到 aha）
2. **多少人答完了第一天**（第一天的词是不是他自己挑的，这个数会说话）
