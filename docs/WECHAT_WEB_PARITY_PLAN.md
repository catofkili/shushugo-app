## 目标与边界

目标是让小程序与其他现有版本的主要功能完全一致；同一账号、学习内容、权益、主题和屏幕宽度下，视觉、文案、入口、状态和交互也尽可能贴近当前 5173 网页。同一学习动作必须产生相同的计划、进度与同步结果。对比对象是**手机宽度的网页**，不是桌面双栏布局。

微信系统控件和底层 API 可以按平台方式接入，但这不自动授权用户可见的产品差异。小程序与 Chrome 的本地数据天然分开；账号绑定与同步后的数据一致性单独验收，不通过复制用户真实数据库来制造“一样”。

### 最高优先级规则：主要功能跨端完全一致

本规则来自用户 2026-09-24 明确确认，适用于小程序、网页以及其他现有客户端中相同的产品功能；5173 手机网页是当前视觉和交互参照。主要功能、操作流程、页面入口、文案、权限、数据格式、状态、计算结果、权益和同步行为必须遵循同一产品定义。渲染技术可以不同（例如 React 与 WXML/WXSS），但不能因此削弱、替换或另造功能。

发现差异时，默认按其他版本的现行行为修复。意外差异是未完成项，不能作为验收通过。若差异确因技术或微信官方要求无法避免，先整理一条审批记录：对比版本、差异的用户可见表现、证据/官方依据、影响范围和最小建议方案；未经用户明确点头，不得把该差异作为产品决定实现、保留、延期或发布。

当前用户预先允许的例外只有微信支付流程，以及为完成相同功能而确有必要、并能对应具体微信 API / 审核要求的少数平台适配。适配只覆盖最小必要的底层差别；支付商品、定价、订单归属、验单、权益和用户数据仍一致。微信原生渲染控件、登录、分享、订阅消息、文件、音频或生命周期 API 等实现方式本身不构成产品差异的普遍授权；它们若改变用户可见功能、步骤、权限或结果，仍须单独征得用户同意。

本计划只写文档，不表示任何页面、真机或已发布版本已经改好。开始编码前重查 `main` 的 HEAD、工作区未提交文件、其他 worktree/分支及远端祖先关系。当前基线是本地 `main` 的 `e1f9d1f`，比 `origin/main` 领先 25 个提交，且两个端都有未提交改动；后续不能直接拿远端分支或干净 archive 当作用户眼前的 5173 版本。

## 已确认的工程现状

- 网页路由以 `frontend/src/types/app.ts` 的 29 个 `Page` 标识和 `frontend/src/App.tsx` 的实际渲染分支为准；手机外壳在 `frontend/src/components/AppNavigation.tsx`，视觉规则在 `frontend/src/design.css`、`frontend/src/app.css` 和皮肤样式中。
- 小程序在 `wechat-miniprogram/src/app.json` 声明 13 个主包页、6 个 `features` 分包页、2 个 `content` 分包页。页面结构与样式仍分别手写 WXML/WXSS；`scripts/shared/entry.ts` 和 `build-shared.mjs` 只共享网页数据层，**不会把 React 页面或 CSS 自动变成小程序页面**。
- 9 月 24 日网页设计系统和组队页面更新没有同步到四张截图涉及的小程序页面。小程序当前组队头图保留英文眉题及动物 emoji，网页已经改用品牌素材；语法、每日量和辨析页也保留另一套容器/控件。
- 四张截图的空白还叠加了小程序本地学习库未就绪：组队页直接显示“先准备好本地学习库”，每日量主体被 `ready` 条件隐藏，语法页将具体异常折叠成“操作失败”。后续模拟器能够显示今日任务和语法条目，说明不能把截图全部解释成“内容根本没有实现”；首次下载失败的原始异常尚未留证。
- 当前开发者工具控制台曾出现 `applyTheme` 调用 `document.documentElement.setAttribute` 的兼容警告。小程序浏览器替身需要覆盖开发者工具实际提供的 `document` 形态；这条警告不等同于四页空白的已证实原因。
- `wechat-miniprogram/README.md` 中部分“尚未接入”叙述早于 9 月 23 日的合并。以现有源码和实测为准，不照着旧待办重复开发。

## 技术路线与排期判断

先沿用现有原生 WXML/WXSS 页面和共享数据层：数据规则在网页源码维护一次，页面把现行手机视觉与交互逐个映射到微信原生组件。当前 21 个小程序页面已经存在，整体改写成另一套框架会同时重做导航、包体、文件和微信接口适配；在证明现有路线无法达到目标前，不引入 Taro 或 WebView 重写。网页 CSS/React 组件不能直接复用为小程序 UI，因此“同一份源码”针对可共用的数据规则，“尽可能一模一样”针对最终页面和行为。

### 唯一业务源与微信专属边界

跨端业务逻辑和持久化协议以 `frontend/src/lib` 为唯一源；小程序用 `scripts/shared/entry.ts` 构建出的 `src/shared/web.js` 调用同一实现。FSRS、每日计划、学习模式、题目与评分、进度、收藏、成就、柚子、周报、权益判据、同步表结构/快照/合并都不得在小程序另写一份。小程序自己的 SQL/文件适配只负责把相同规则接到本地 SQLite 和微信文件系统，不得改变规则。

小程序可以独立实现的只有微信运行所必需的薄适配：WXML/WXSS 渲染及事件转发、`wx.login`/微信授权、虚拟支付调起与微信回调协议、订阅消息、系统分享、微信云存储/文件 API、原生音频和生命周期桥接。支付的前端步骤受微信 API 约束，但商品目录、订单归属、验单、价格校验、权益授予/撤销和用户数据仍以 Worker 与共享权益模型为准；不得另造本地发货或第二份会员状态。

组队、词库、学习计划等同时存在于网页与小程序的产品功能不是“小程序专属”。可以有两套原生视图，但入口、字段、服务端校验、权限、状态和用户可见结果须遵循同一产品定义；微信登录/分享等个别调用才走平台适配。任何新增的小程序专用业务分支都必须先证明是微信审核/API 的硬要求，并记下官方约束与对应适配位置；“做起来方便”或“微信用户习惯不同”不构成例外。

依赖顺序是参照与测试状态 → 初始化/运行时 → 外壳与设计变量 → 全部页面 → 跨端行为 → 模拟器/真机验收。按一名开发者全职投入，当前粗估 **20–40 个工作日（约 4–8 周）**：参照和运行时约 3–6 日，外壳与素材约 3–6 日，逐页适配约 10–20 日，回归、模拟器与真机验收约 4–8 日。这是规划范围，不含等待平台审核或外部服务配置的时间，也不是承诺日期。首页、语法和组队作为三种页面形态的实现样本，用实际素材装包、布局限制和单页耗时校准总工期；**样本验收不替代后续全部页面**。

## 对齐方法

### 1. 冻结可比较的参照

1. 在**独立目录**保存同一时刻的网页源码、现有未提交改动和小程序源码。不要切换、stash、覆盖当前 5173 工作目录；不要把 `frontend/.local/live.db` 或真实浏览器 IndexedDB 带入预览。
2. 网页预览只用独立端口和测试浏览器资料；小程序用开发者工具的独立测试项目/本地数据。5173 学习标签页不导航、不刷新、不触发 HMR。全部改好之后，才安排对正在学习的网页做一次可见更新。
3. 固定同一组测试状态：首次启动且无库、下载中、下载失败、离线恢复、空白学习进度、已有进度、今天完成、未登录/已登录、免费/Pro、浅色/深色、默认/已购买皮肤、窄屏/常见手机宽度。网页用合成库和假账号数据；云端、支付和真实个人学习库不参与视觉基线。
4. 为每个状态记录网页与小程序截图、入口路径、可点击动作、具体差异及平台例外。参考图要标明源码 HEAD、未提交改动摘要、设备宽度和测试数据版本，避免后来拿不同版本的两张图比较。

### 2. 先修“空白壳”和运行时基础

- 对所有依赖本地库的页建立明确的“未下载 / 下载中 / 可重试错误 / 已就绪”状态。`ensureDatabase`、`restoreDatabase`、内容分包装载的失败应保留具体错误码和可操作提示；控制台记录原始异常，用户界面不暴露敏感路径或内部堆栈。不要让 `ready=false` 只剩标题和大片空白。
- 检查首次下载、冷启动恢复、云存储 fileID、分包加载和 seed 版本校验；用失败注入和离线测试证明重试能恢复，且不会覆盖已经保存的个人学习库。
- 修正共享层浏览器替身的主题警告，并检查相同的 DOM 假设是否出现在主题、动效、柚子装备和偏好事件入口。只改小程序平台替身，不给网页源码到处加针对微信的分支。
- 保证每页等待 `database-store.ensureContentLoaded()` 的顺序；共享数据构建与内容分包仍按当前包体约束工作。运行时基础稳定后才做大规模视觉重排，否则漂亮页面仍可能显示空白。

### 3. 对齐整体外壳与设计语言

- 用 `design.css` 的三层表面、文字三档、主/次操作、阴影、间距、圆角和字号制定小程序 WXSS 对照值。微信 WXSS 不直接照搬浏览器 `color-mix`、Tailwind 或 DOM 选择器；把最终颜色和可实现的效果落成小程序变量/公共样式，保持同一视觉结果。
- 对齐手机顶栏与四个 Tab 的信息层级、标题、返回规则、安全区和滚动空间；清理系统导航标题与页内大标题重复、返回键重复、底部遮挡。微信胶囊与原生导航保留平台边界。
- 复用现有 `frontend/public/brand/` 的品牌图、贴纸、图标及状态画面，不重新画另一套动物或临时 emoji。按主包/分包预算放置与压缩素材，关键离线画面要有本地资源；任何素材新增都要复查每包 2 MiB 限制。
- 主题与柚子皮肤在首页、学习卡、弹层、子页面及 TabBar 同步切换。浅色、深色、默认皮肤和至少一种已购皮肤都要做截图比较；不能只对默认浅色截图调色。
- 空状态、加载、错误、确认、会员提示统一沿用网页现行表达（吉祥物提示、控件主次、中文短标题），去掉与网页设计系统冲突的英文大写眉题和模板式占位文案。

### 5. 行为与数据一致性

- 网页已有的计划、出题、FSRS、收藏、成就、词汇量、柚子、周报、同步判据，继续从 `scripts/shared/entry.ts` 打包；平台适配仅处理 SQLite 句柄、文件、微信 API 和确实无法共用的 UI。发现页面本地重新计算同一个指标时，先对照网页来源并消除重复规则。
- 对同一合成数据库跑两端操作路径：新学、答错/撤回、语法掌握、辨析标记与连线、词汇量结果、每日量调整、收藏、柚子购买与装备、周报生成和云同步往返。检查实际表/字段/版本、显示数字和下一张卡，不能只比 smoke 测试是否退出 0。
