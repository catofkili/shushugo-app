# JLPT 刷题：原创出题流水线

规则和调度脚本的**仓库副本**。实际干活的目录是 `~/Documents/shushugo-wt/_codex/jlpt-trial/`（脚本里写死了这个路径，
题稿、Codex 日志、审校记录都在那里，体积大、不进仓库）。那个目录丢了的话，从这里拷回去就能接着出下一套。
改规则时两边一起改。

| 文件 | 用途 |
|---|---|
| `rules.md` | 出题规则（各题型怎么出、干扰项怎么选、通用质量线、`questions.json` 格式） |
| `review.md` | 审校规则：另开一个 Codex 会话，先盲做、再对答案、再直接改题；附卷 1、卷 2 验收时改掉的几类毛病 |
| `run-job.sh` | 一份题（一级一科）的流水线：Codex 手写 → 另一个 Codex 会话审校。`OUT=…/setN` 写到第 N 套；提示里自动列出前几套用过的考点；`REVIEW_ONLY=1` 只补审校；`JLPT_CODEX_HOMES="$HOME/.codex-b $HOME/.codex"` 按顺序换号，日志里有「your usage limit」就换下一个 |
| `gen-set3.sh` | 出一整套卷的调度：同时最多 4 个 Codex（`xargs -P 4`），可反复跑，10 份全部 `DONE` 才写 `SET3-DONE`。出卷 4 照抄改套号即可 |
| `show.cjs` | 验收用：`node show.cjs set3/N1-grammar/questions.json [起] [止]` 逐题打印题干、✔正解、错项说明、排序、解析、doubt，文章题先印文章 |
| `fix.cjs` | 验收用：`node fix.cjs <questions.json> <改动.js>` 按题号改题，改动文件可重复执行，打完印正解位置分布和 doubt 数 |
| `acc3/` | 卷 3 验收时 Claude 的逐题改动（每条带一行为什么改），也是下一套验收的「常见毛病」样本 |
| `repair1010/` | 2026-10-10 普查返修：`dump.py` 读被标题的题、`p_N?.py` / `p_N?_passages.py` 是逐题补丁（每条带原因）、`apply.py` 演示 / 写入并校验。**已入库的卷 1–3 以题库 JSON 为准**，这些补丁只是记录，别拿旧的 `questions.json` 重新导入覆盖 |

## 分工（作者定的）

- 题目由 Codex（`gpt-6-luna`、max 推理、fast）**手写**，不许写脚本生成题目。作者原话「不要脚本，规则给 luna max，它手写」。
- 审校是另一个 Codex 会话，不看答案先做一遍，再对答案、改题。
- Claude 逐题验收（读每一道题、改题），再导入题库、跑校验、提交。
- 红蓝宝书等市售题集**一道题都不给 Codex**，只给 Claude 看来总结套路。

## 导入

```bash
cd frontend
node --no-warnings scripts/build-jlpt-bank.mjs --src ~/Documents/shushugo-wt/_codex/jlpt-trial/set2 --set trial2 --title "试做卷 2"
npm run verify:jlpt-bank
```

导入器先在内存里合并、校验，**全过了才写盘**；缺一科、某科没有 `DONE`、`no` 不连续、还有 `doubt`，都拒绝导入。
校验（`verify-jlpt-bank.mjs`）除了格式，还卡：每套卷每级各题型的题数（`SET_COUNTS`）、每科正解位置相差不超过 2（导入时已经洗过，这条只是兜底）、
同一级跨套不重复考点、每个错项都有中文说明、文章空号按出现先后递增。唯一正解、日语自然不自然，只能靠人读。

## ⚠️ 返修时踩的坑（2026-10-10）

- **打乱选项不改解析正文**：`shuffleAnswers` 会重排 `options`、同步改 `order` 和 `distractors` 的键，**但不会改 `explanation` 里写的「第三句」「[3,4,1,2]」**。
  卷 1–3 因此有 11 题解析指错（N3 4、N4 4、N5 3）。现在 `rules.md` 第 25 条禁止写编号，`verify-jlpt-bank.mjs` 兜底检查（解析里的「第N句／项」「[a,b,c,d]」和现在的 answer / order 对不上就报错，自测在 `--self-test`）。
- **改排序题要把相邻的块合成一块**：「話せば／話すほど／お互いのことが／分かってくる」有 3→1→2→4 的第二种语序；
  合成「話すほどお互いの／ことが」后才唯一。同类：「手を触れては」「私が探していた」「記入する必要はなく」。
  改完用 `apply.py` 校验 ★ 位置上的 order 选项号等于 answer。
- **换了文章要把每个空的 `explanation`、`distractors` 都重写**，不能只换文章：旧的说明里写着旧文章的情节（图书馆、料理会、母亲、鱼），留着就是「解析加了题干没有的事实」。
- **sol 给的替换干扰项也要检查第二正解**：「会社の先行きを疑って」接近「危ぶんで」、「食材費を担う」成立、「軽薄な」可能成立——这些没改。
  一律先问「母语者在真考场上会不会也认为对」，会就不换。
- **定义式题干**（「このように、出せる最後の日時を（　）という」）比情景式更能锁定唯一答案，「期限／日程」「待ち合わせ／相談」这类近义词题适合用。
