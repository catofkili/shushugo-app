# JLPT 刷题：原创出题流水线

规则和调度脚本的**仓库副本**。实际干活的目录是 `~/Documents/shushugo-wt/_codex/jlpt-trial/`（脚本里写死了这个路径，
题稿、Codex 日志、审校记录都在那里，体积大、不进仓库）。那个目录丢了的话，从这里拷回去就能接着出下一套。
改规则时两边一起改。

| 文件 | 用途 |
|---|---|
| `rules.md` | 出题规则（各题型怎么出、干扰项怎么选、通用质量线、`questions.json` 格式） |
| `review.md` | 审校规则：另开一个 Codex 会话，先盲做、再对答案、再直接改题；附卷 1、卷 2 验收时改掉的几类毛病 |
| `run-job.sh` | 一份题（一级一科）的流水线：Codex 手写 → 另一个 Codex 会话审校。`OUT=…/setN` 写到第 N 套；提示里自动列出前几套用过的考点；`REVIEW_ONLY=1` 只补审校；`JLPT_CODEX_HOMES="$HOME/.codex-b $HOME/.codex"` 按顺序换号，日志里有「your usage limit」就换下一个 |
| `gen-set3.sh` | 出一整套卷的调度：同时最多 4 个 Codex（`xargs -P 4`），可反复跑，10 份全部 `DONE` 才写 `SET3-DONE`。出卷 4 照抄改套号即可 |
| `show.cjs` | 验收用：`node show.cjs set3/N1-grammar/questions.json [起] [止]` 逐题打印题干、✔正解、错项说明、排序、解析、doubt，文章题先印文章 |
| `fix.cjs` | 验收用：`node fix.cjs <questions.json> <改动.js>` 按题号改题，改动文件可重复执行，打完印正解位置分布和 doubt 数 |
| `acc3/` | 卷 3 验收时 Claude 的逐题改动（每条带一行为什么改），也是下一套验收的「常见毛病」样本 |

## 分工（作者定的）

- 题目由 Codex（`gpt-6-luna`、max 推理、fast）**手写**，不许写脚本生成题目。作者原话「不要脚本，规则给 luna max，它手写」。
- 审校是另一个 Codex 会话，不看答案先做一遍，再对答案、改题。
- Claude 逐题验收（读每一道题、改题），再导入题库、跑校验、提交。
- 红蓝宝书等市售题集**一道题都不给 Codex**，只给 Claude 看来总结套路。

## 导入

```bash
cd frontend
node --no-warnings scripts/build-jlpt-bank.mjs --src ~/Documents/shushugo-wt/_codex/jlpt-trial/set2 --set trial2 --title "试做卷 2"
npm run verify:jlpt-bank
```

导入器先在内存里合并、校验，**全过了才写盘**；缺一科、某科没有 `DONE`、`no` 不连续、还有 `doubt`，都拒绝导入。
校验（`verify-jlpt-bank.mjs`）除了格式，还卡：每套卷每级各题型的题数（`SET_COUNTS`）、每科正解位置相差不超过 2（导入时已经洗过，这条只是兜底）、
同一级跨套不重复考点、每个错项都有中文说明、文章空号按出现先后递增。唯一正解、日语自然不自然，只能靠人读。

## ⚠️ 踩过的坑

- **并行的 Codex 一次别超过 5 个左右**：2026-10-02 一口气开了 13 个（max + fast），25 分钟把整个账号额度用光。
- **旧 `gen-sets.sh` 不看退出码就写 `SETN-DONE`**，`run-job.sh` 又把上一次残留的 `review.md` 当成审完：卷 3 第一次全部撞额度失败，
  目录里照样有 `SET3-DONE`。现在 `run-job.sh` 审校前先删旧 `review.md`、看退出码、日志里有「usage limit」就记 `FAILED`；
  `gen-set3.sh` 逐个检查 `DONE`。**`SETN-DONE` 只说明流水线跑完了，不说明题能用**——最后一道关是 Claude 逐题验收。
- **工作目录别放 `/private/tmp`**：2026-10-04 另一个 Codex 会话在 `/private/tmp` 里重出了卷 3、改了一批代码，
  撞额度停下后机器一重启全没了。
- **正解位置 1234 1234 循环**（2026-10-08 查出）：规则写「1、2、3、4 各出现的次数相差不超过 2」，Codex 就按 1234 循环排，
  卷 1、卷 2 十科里有七科是这样，审校和我的验收都没拦住（每科计数确实均衡）。背下规律就能蒙对，盲做审校也被规律带着走
  （卷 3 的 N1 语汇盲做结果就是 1234 循环）。现在正解位置不靠出题人：`build-jlpt-bank.mjs` 的 `shuffleAnswers`
  在 `run-job.sh` 审校前洗一遍、导入时按「套卷-等级-科目」再洗一遍（种子固定，重导同一份源结果不变），
  规则里那条改成「不用管」。卷 1、卷 2 已按新导入器重导（源文件没动，482 题逐题核对过正解文字、错项说明、排序都跟着走了）。
  代价：之前在实验开关里答过的题，`jlpt_answers.chosen` 记的是旧选项号，结果页「你的选择」会对不上（对错 `correct` 不受影响）。
- **后台流水线要脱离 Claude 会话启动**：2026-10-06 卷 3 重出撞额度后会话结束，进程一起被杀，留下五份写了一半的审校、
  没有 `DONE` 也没有 `FAILED`。现在 `gen-set3.sh` 可以反复跑（有 `DONE` 跳过、有 `questions.json` 只补审校），
  用 `os.setsid()` 启动，命令写在脚本开头。
- **变量后面紧跟全角字符要加花括号，脱离启动时还要设 `LANG=en_US.UTF-8`**：2026-10-08 `$LV　科目` 在 C 语言环境下被当成
  `LV<全角空格的第一个字节>` 解析，报 unbound variable，提示头整段没了。Codex 照样出题，但不知道级别和前几套考点：
  N1、N2 文法题数不对、和前两套撞了 9–11 个考点，整份作废重出（坏稿在 `_codex/jlpt-trial/_discard-set3-1008/`）。
  现在写成 `${LV}　`；以后改脚本，凡是后面紧跟中日文字符的变量一律带花括号。`bash -n` 查不出这个问题，它只在运行时报错。
- 审校会「压缩题干」，压缩时把空后面属于句子的词删掉（卷 1 语形成「（　）可能」）；排序题常有第二种语序让 ★ 换块。验收时专门看这两类。
