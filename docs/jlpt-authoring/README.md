# JLPT 刷题：原创出题流水线

规则和调度脚本的**仓库副本**。实际干活的目录是 `~/Documents/shushugo-wt/_codex/jlpt-trial/`（脚本里写死了这个路径，
题稿、Codex 日志、审校记录都在那里，体积大、不进仓库）。那个目录丢了的话，从这里拷回去就能接着出下一套。
改规则时两边一起改。

| 文件 | 用途 |
|---|---|
| `rules.md` | 出题规则（各题型怎么出、干扰项怎么选、通用质量线、`questions.json` 格式） |
| `review.md` | 审校规则：另开一个 Codex 会话，先盲做、再对答案、再直接改题；附卷 1、卷 2 验收时改掉的几类毛病 |
| `run-job.sh` | 一份题（一级一科）的流水线：Codex 手写 → 另一个 Codex 会话审校。`OUT=…/setN` 写到第 N 套；提示里自动列出前几套用过的考点；`REVIEW_ONLY=1` 只补审校 |
| `gen-set3.sh` | 出一整套卷的调度：每批 5 个 Codex，10 份全部 `DONE` 才写 `SET3-DONE`。出卷 4 照抄改套号即可 |

## 分工（作者定的）

- 题目由 Codex（`gpt-6-luna`、max 推理、fast）**手写**，不许写脚本生成题目。作者原话「不要脚本，规则给 luna max，它手写」。
- 审校是另一个 Codex 会话，不看答案先做一遍，再对答案、改题。
- Claude 逐题验收（读每一道题、改题），再导入题库、跑校验、提交。
- 红蓝宝书等市售题集**一道题都不给 Codex**，只给 Claude 看来总结套路。

## 导入

```bash
cd frontend
node --no-warnings scripts/build-jlpt-bank.mjs --src ~/Documents/shushugo-wt/_codex/jlpt-trial/set2 --set trial2 --title "试做卷 2"
npm run verify:jlpt-bank
```

导入器先在内存里合并、校验，**全过了才写盘**；缺一科、某科没有 `DONE`、`no` 不连续、还有 `doubt`，都拒绝导入。
校验（`verify-jlpt-bank.mjs`）除了格式，还卡：每套卷每级各题型的题数（`SET_COUNTS`）、每科正解位置相差不超过 2、
同一级跨套不重复考点、每个错项都有中文说明、文章空号按出现先后递增。唯一正解、日语自然不自然，只能靠人读。

## ⚠️ 踩过的坑

- **并行的 Codex 一次别超过 5 个左右**：2026-10-02 一口气开了 13 个（max + fast），25 分钟把整个账号额度用光。
- **旧 `gen-sets.sh` 不看退出码就写 `SETN-DONE`**，`run-job.sh` 又把上一次残留的 `review.md` 当成审完：卷 3 第一次全部撞额度失败，
  目录里照样有 `SET3-DONE`。现在 `run-job.sh` 审校前先删旧 `review.md`、看退出码、日志里有「usage limit」就记 `FAILED`；
  `gen-set3.sh` 逐个检查 `DONE`。**`SETN-DONE` 只说明流水线跑完了，不说明题能用**——最后一道关是 Claude 逐题验收。
- **工作目录别放 `/private/tmp`**：2026-10-04 另一个 Codex 会话在 `/private/tmp` 里重出了卷 3、改了一批代码，
  撞额度停下后机器一重启全没了。
- 审校会「压缩题干」，压缩时把空后面属于句子的词删掉（卷 1 语形成「（　）可能」）；排序题常有第二种语序让 ★ 换块。验收时专门看这两类。
