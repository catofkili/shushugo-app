# 手写 JLPT 题：Claude 子代理任务书

你负责若干份「一级一科」的题（见你的任务里的清单，按顺序一份一份做，前一份做完再开下一份）。
流水线目录：`/Users/lsc/Documents/shushugo-wt/_codex/jlpt-trial`（下称 TRIAL）。

## 每份题的做法
1. 生成任务书：`cd TRIAL && JLPT_REPO=$HOME/Documents/shushugo ./gen-more.sh prompt <套号> <科目>`（比如 `prompt 5 N4-grammar`）。
   会写出 `TRIAL/set<套号>/<科目>/write.prompt.md`。**这份文件就是你这一份的完整任务书**（本次任务、已用过的考点黑名单、全部出题规则、`questions.json` 格式），
   **从头到尾读完再动手**，规则以它为准。每一份都要重新生成（黑名单会随前一份更新）。
2. **每道题自己手写**，不许写脚本批量生成题目。可以用 sqlite3 只读查词表和语法表选考点（命令在任务书里）。
3. 写完先存成 `questions.tmp.json`，自己通读一遍、按任务书的自查要求改完，再 `mv questions.tmp.json questions.json`（**questions.json 只能是完整成品**；中途不要留半成品）。同目录再写 `self-check.md`（犹豫过的题号和原因、考点覆盖）。
4. 交付后跑两个检查，有问题当场改：
   - `node TRIAL/show-compact.cjs <questions.json>`：把整份打印出来通读，特别看正解是不是唯一、日语自然不自然、解析和正解是不是对得上；
   - `node TRIAL/check-key-vs-explanation.cjs <questions.json>`：粗筛「解析里引的是另一个选项」。
5. 做完这一份，**不要删 `CLAIMED`**（那是给调度脚本看的标记，主会话统一撤）。

## 硬限制
- 只在你负责的目录里写文件。不提交、不起服务器、不碰仓库代码。
- 不许读、不许搜任何真题或题集（含 `~/日语题/`），不凭记忆复现见过的题。
- 题干新写，不照抄词库 `example_jp`。
- 质量比数量重要，但题数必须和任务书表里的一致。正解位置不用管（导入时会洗）。
- 常见毛病（前几套审校出过）：解析写了题干没有的事实、排序题有第二种语序、文章前后自相矛盾、干扰项其实也成立（第二正解）、
  时态没锁死、用法题错句是胡话。每道题出完问自己：「母语者在考场上会不会认为另一个选项也对？」会就换。
