# 连胜（火苗）规格（2026-10-14 立项）

> 作者原话：「我打算为连胜这个概念增加光彩，全力 all in 这个东西的效果优化」。
> 起因见 `docs/DUOLINGO_DESIGN_STUDY.md` §3.3。作者 10-14 定了三件事：
> ① **两档**：一天里学满一小段 = 火苗亮；清完当天计划 = 火苗变金；
> ② 范围：打卡当刻全屏庆祝、里程碑特别版 + 火苗进化、连胜详情页、「快断了」状态 + 提醒，**网页和小程序一起做**；
> ③ 动画只用 CSS + 现有吉祥物贴纸，不引 Lottie / Rive。

## 0. 改之前是什么样

- 打卡 = `checkins` 表一行（`word-api.ts` 的 `recordCheckin()`，**清完今日单词计划**才写；补签也写这张表）。
  同步策略 `union`。
- 连胜天数 `computeStreak(checkins, today)`（`lib/zoo-streak.ts`）：今天没打卡就从昨天往前数，「断签不惩罚」。
- 用到它的地方：主页问候条火苗 chip（`ZooHome.tsx`）、7 日连击 +300 柚子（`yuzu.ts settleYuzu`）、
  补签可补的日子（`yuzu.ts repairableDays`）、完成页日历（`WordStudyPanels.tsx FinishPanel`）、
  打卡分享图（`share-card.ts streakDays`，自己又写了一份同样的循环）。
- **没动、也不许跟着动的**：组队打卡（`team-activity.ts` / `TEAM_STREAK_AND_DUEL_SPEC.md`，有自己的过关线 30 词 + 10 分钟）；
  成就的 `longestDayStreak`（「连续 N 天有学习记录」，口径是「有任何记录」，和火苗不是一回事，成就已发出去的不能收回）。

## 1. 判据（全部现算，不新建表、不改 schema）

沿用「成就：判据现算，不攒计数器」的原则。**不新增表**：新增同步表要改 `local-schema.sql`、`web.js`、
同步登记，而下面的判据全部能从已经同步的表里算出来，还能自动追溯历史。

学习日一律用 `today()`（凌晨 4 点切）和表里已有的 `reviewed_on` / `studied_on` / `checked_on`，不碰本地时区。

| 名称 | 判据 |
| --- | --- |
| **金 gold(D)** | `checkins` 有 D，且 D **不是**补签补的（`yuzu_ledger` 里没有 `kind IN ('repair','repair_card') AND key = D`） |
| **补 repaired(D)** | `checkins` 有 D，且是补签补的 |
| **亮 lit(D)** | gold 或 repaired，**或** 当天作答 ≥ 20 次，**或** 当天有效学习 ≥ 300 秒 |
| 作答次数 | `reviews` + `grammar_reviews` + `kanji_unit_reviews` 当天行数；表存在时再加 `spelling_reviews`、`jlpt_answers`（按各自的日期列） |
| 有效学习秒数 | `word_study_time.seconds`（已是跨设备汇总，见 `lib/sync/study-time.ts`） |
| **连胜 streak** | 今天亮就从今天、否则从昨天起，往前数连续亮的天数（「今天还没学不算断」照旧） |
| **最长连胜** | 所有亮的日子里最长的一段 |
| **快断了 atRisk** | streak > 0、今天没亮、本机时钟 ≥ 20:00（或 < 04:00，仍属同一学习日） |

- 阈值 20 次 / 300 秒是**默认值**，作者可改；写成 `STREAK_LIT` 常量一处。
- ⚠️ `spelling_reviews` / `jlpt_answers` 是 `cloud:false`，只在本机。换设备后那几天可能只靠学习时长判亮 —— 接受。
- ⚠️ 判据变宽后，作者过去「学了但没清完计划」的日子会**追溯变亮**，连胜数可能变大。这是有意的。

## 2. 跟着换口径的地方

- **2026-10-14 作者定：「小火苗保连胜，大火苗得奖励」**——7 日连击 +300 改成「同一段连胜里每攒满 7 个大火苗（金）发一次」（`goldInStreak`），小火苗和补签只保连胜不断、不算数。下面这句是初版，已作废：
- `settleYuzu` 的 7 日连击 +300：改成「今天亮且 streak % 7 == 0」。⚠️ 这是**柚子经济的改动**（门槛从清完计划降到学满一小段），
  上线前要作者点头；`book("streak", day)` 幂等，不会给历史补发。
- `repairableDays`：「洞」改成**没亮**的日子（原来是没打卡）。第一次亮之前的日子不算洞。补签仍写 `checkins`，
  判据上它算 repaired（亮，不金）。
- 分享图 `streakDays`：删掉自己那份循环，用新模块；「累计打卡」改成累计亮的天数。
- 完成页日历：格子分四态 —— 金 / 亮 / 补 / 没亮（今天单独描边）。
- 主页 chip 的数字：用新模块的 streak。

## 3. 火苗：一个组件，三种状态 × 五级进化

`<StreakFlame state tier size />`，纯 CSS（层叠的水滴形 `border-radius` + 渐变 + 深棕描边，
和吉祥物贴纸同一种圆润手绘感）。**不用内联 SVG**（小程序不渲染）、**不用 lucide**（小程序里是 Image，染不了色）。

- **状态**（今天）：`off` 灰、轻微缩小（今天没亮）；`lit` 暖橙，火舌微微跳动；`gold` 金色 + 一道高光周期扫过。
  `atRisk` 时 `off` 的火苗每 3 秒左右晃一下。
- **进化**（按 streak）：
  1. 1–6 天：单层小火苗
  2. 7–29：加外焰 + 两三颗上飘的火星
  3. 30–99：内芯变蓝
  4. 100–364：外面一圈缓慢转动的光环
  5. 365+：头上一顶小冠
- 静止形态（减少动效 / 暂停）就是最终态：所有动画只做「跳动 / 扫光 / 飘」，**基础样式必须是终态**
  （`interface-and-design-system.md` 周报那节的坑）。

## 4. 打卡当刻

### 4.1 学习中：不打断，只冒一下
当天第一次跨过「亮」的那一刻（任何学习页），屏幕顶部滑下一枚小胶囊「火苗 + 今天亮了」，1.6 秒自己收回，
`pointer-events:none`，轻震一下。**不在答题中弹全屏**（多邻国也从不在一课中间打断）。

### 4.2 全屏庆祝：在下一个停顿处
挂一个常驻层 `StreakCelebrationHost`（和 `PersistenceBanner` 同层），有「今天待庆祝」时，在以下时机放：
- 单词完成页 `FinishPanel` 出现时（清完计划 = 金，通常和亮一起放）；
- 其它学习模式自己的结束页（语法考题、拼写、JLPT 等）出现时；
- 回到主页时。

每个学习日每一级（亮 / 金）**每台设备只放一次**，记在 localStorage `mn-streak-celebrated:<学习日>`（设备偏好，不同步）。

编排（总长约 2.8 秒，之后停在终态等用户点「继续」）：
1. 0 ms：底色压暗淡入；
2. 150 ms：火苗从一个火星「点燃」—— 放大回弹，外圈一圈光晕扩散，配 `playStreakChirp` + 重震；
3. 600 ms：天数**翻牌** N → N+1（旧数字上滑淡出，新数字从下弹入）；
4. 900 ms：本周 7 格依次点亮（每格 70 ms），今天那格最后亮、溅一圈火星；
5. 1400 ms：吉祥物（`mood-fired-up`）从火苗旁边探出来，说一句（见 §7）；
6. 1700 ms：「继续」按钮浮上来。

- **变金**：亮的那一版放完后（或同时达成时接在后面），火苗由橙渐变成金，一道扫光，格子里今天那格换金色，吉祥物 `mood-proud`。
- **里程碑**（7 / 14 / 30 / 50 / 100 / 200 / 365 / 500 / 1000）：火苗身后转动的光芒、`ZooConfetti`、
  一枚「N 天」徽章盖章落下；7 的倍数同时显示 +300 柚子数上去。吉祥物 `mood-yay`。
  火苗升级（跨进新的一级进化）的那天，火苗先按旧级出现，再「蜕变」成新级。
- **第一天**（streak = 1 且之前从没亮过）：文案讲规则 —— 明天再来，它就会长大。
- **重新点燃**（streak = 1 但以前亮过 ≥ 3 天）：文案不责备；7 天内有可补的洞时给「补签」次按钮（进详情页）。

## 5. 连胜详情页（新路由 `streak`）

主页火苗 chip 点进来。从上到下：
1. 大火苗（当前进化 + 今天状态）+ 大号天数 +「连续天数」；没亮时下面一行吉祥物说话提示今天还差多少（按作答次数 / 分钟里离得近的那个说）。
2. 两格数：最长连胜、累计亮的天数。
3. 下一个里程碑：进度条（例 23 / 30）+ 里程碑徽章一排（拿到的实心、没到的虚线空槽，和成就页同一种语言）。
4. 月历（可左右翻月）：金 / 亮 / 补 / 没亮 四态；最近 7 天里没亮的格子上有「补」按钮，走现有 `repairDay` / `repairDayWithCard`（柚子商店那份入口保留）。
5. 一行规则说明，吉祥物说：学满一小段就亮、清完计划变金。

登记：`types/app.ts`、`routes/`、`navigation-titles.json`（`mobileTitles`）、Taro `content-pages/streak`（照 `achievements` 的写法）。

## 6. 快断了 + 提醒

- 主页：`atRisk` 时 chip 里的火苗是 `off` 并晃动；问候气泡的那句换成「连续 N 天，今天还没点火」（只在 atRisk 时）。
- iOS 本地通知（`lib/notifications.ts`）：每日提醒的文案在 streak > 0 时换成带天数的版本；**今天已经亮了就不再发今天的提醒**
  （打开 App、跨过亮的时候重排当天这一条）。具体怎么重排按 notifications.ts 现有的排程方式做，不另起一套。
- 小程序：订阅消息要作者去公众平台申请模板 ID，**这一轮不做**，只做页面内的 atRisk 表现。

## 7. 文案（Claude 写，作者可改）

- 小胶囊：「今天的火苗亮了」
- 庆祝页标题：「连续 N 天」；副句按情况：
  - 第一天：「点着了。明天再来，它会长大一点。」
  - 平常：「火苗又旺了一点。」
  - 变金：「今天的计划清完了，火苗变金。」
  - 里程碑：7「一整周。」14「两周没断。」30「一个月了。」50「五十天。」100「一百天。」365「一整年。」
  - 进化当天追加一句：「火苗长大了。」
  - 重新点燃：「重新点着了。」
- 详情页规则：「学满一小段，火苗就亮；清完当天计划，它会变金。」
