# 每周复习周报（“二楼”）设计规格 · 修订建议

> 首次核对：2026-09-11；2026-09-12 更新：第 14 节的最终口径已由产品负责人采用，基础闭环已实现。第 13–16 节记录当前实现和仍需发布环境验收的项目；前文建议保留为决策依据。
> 对照原稿：[设计规格](./WEEKLY_REPORT_DESIGN.md)、[开发规划](./WEEKLY_REPORT_PLAN.md)。两份原稿保留。
> 配套实施与验收：[开发规划修订版](./WEEKLY_REPORT_PLAN_REVISED.md)。本文件负责用户体验与业务规则；配套文件负责技术路径、证据和交付顺序。

## 1. 本次审查结论

值得保留的是：周报作为轻松的回顾、事实数字配简短表达、主动查看、离线阅读、安静触达、独立视觉空间。这些可以构成清楚的产品特色。

需要修改的是：不能用“用户不会对账”支撑数据与文案的不一致；不能一边定位轻度用户，一边只让每周学习至少 6 天的人获得内容；也不能把固定乐观日期当作持续更新的预测。复杂手势、云存储、动效和推送都应建立在可靠的周报内容之上。

| 原稿的问题 | 影响 | 本稿建议 |
|---|---|---|
| “零负反馈”同时要求隐藏一切不理想信息 | 可能演变成假预测、假比较，甚至隐藏真实错误 | 不羞辱、不催促，但事实必须准确；必要错误照常说明 |
| 每周 >5 天才生成，称为保护轻度用户 | 恰好排除了每周学 1–5 天的人；原风险对策没有改变这个机制 | 有有效词汇作答就可生成，按材料多少缩减页数 |
| “本周”推送与“上一周”楼层混用 | 日期范围容易错一周 | 统一为“这一周的回顾”，封面明确显示统计区间 |
| 速度对标来自粗略累计量除以年龄或学年 | 累计存量不是特定阶段的新增速度，母语词汇增长也不等于外语首次作答 | 首发停用人群速度对标，保留自己的实际投入与接触量 |
| 精确到日，且预测只提前不推后 | 学习减速后仍展示过时承诺，日期经过后可能还没达标 | 首发不展示 ETA；后续只做条件估计，见第 7 节 |
| P5 使用“该处理的”“差一点点就拿下了” | 与不施压原则冲突，错误频次也不能证明快掌握 | 改为可跳过的“再见一面”，只陈述真实学习记录 |
| 累计“只涨不跌”“至少一个数字必增长” | 删除、重置、导入、去重会改变累计；纯复习也不保证词数增长 | 删除单调增长承诺；只保证有真实、可理解的内容 |
| 无限楼层 + 横向翻页 + 留白死区 | 点击、文本滚动、斜滑、辅助技术等输入仍会冲突 | 保留二楼概念，增加可见入口、关闭按钮与周列表 |
| 默认特效可以“令人厌烦” | 没有可操作的体验标准 | 每页一次主要动效，不阻挡阅读和退出；系统减弱动态效果优先 |
| 历史永久保存、免费历史、本周免费没有统一边界 | 用户无法判断失去订阅后还能读什么 | 本地已有历史免费；Pro 提供云端历史恢复与跨设备同步 |

以上是建议变更，不是把原稿中的“已定”自行解释成新的授权。开发前按第 12 节确认采用哪一套规则；本稿已经给出一致的默认方案，避免把缺口继续留给实现者猜。

## 2. 目标与原则

**目标：让用户看到这一周真实发生过的学习，并愿意轻松地再回来。** 周报打开率只能说明入口是否被找到，不能单独证明留存改善。

1. **准确且温和。** 不用排名、差距、未达标、错过、补齐任务制造压力；不把“学过”写成“掌握”。
2. **查看自愿。** 不打断正在答题的会话，不自动全屏弹出，不做未读红点或反复催看。
3. **内容随材料变化。** 允许短周报，允许省略不适用的模块，不为了六页硬凑数字。
4. **先保护学习，再展示周报。** 浏览、翻页和分享不改变 FSRS、学习队列或当日计划；加入复习必须由用户明确点击。
5. **门槛不作为激励工具。** 不显示“再学一天解锁”；无数据时没有更新提醒。用户主动进入空历史时，可以平静解释“这里会保存你的学习回顾”。

不采用机械的单字禁用作为唯一验收。例如“差”可能出现在日语词条里；按钮和错误提示也需要表达限制。验收对象是周报叙事是否贬低、催促或误导，词条本身不因汉字命中而删改。

## 3. 统计范围与发布时间

### 3.1 首发范围

先做**词汇复习周报**：统计正向词汇作答。反向、语法、汉字题暂不混入同一套数字；页面用“词汇回顾”明确范围。这是为了与现有可核对的数据层一致，不应把其他模式的学习称为“没有学习”。

若最终决定做“全部学习周报”，必须先补充各模式的有效作答与时长定义，按日期并集计算活跃天数，并按词汇、语法等维度分别呈现，不能直接把题数相加后称为词数。

### 3.2 一周的精确定义

- 保留现有代码的周日开周，沿用学习日 04:00 边界。
- 一个完整统计窗口是：周日 04:00（含）至下周日 04:00（不含），日期标签为前一个周日至周六。
- 例如 **2026-09-13 周日发布的回顾，覆盖 2026-09-06 04:00 至 2026-09-13 04:00，封面写“9 月 6 日—9 月 12 日”**。
- 周日 03:59 的作答仍属于刚结束窗口；04:00 的作答属于新窗口。
- 04:00 后可在用户打开应用、返回前台或完成数据合并后生成。外部提醒建议时间为周日 16:00，具体送达能力见第 9 节。
- 顶部更新提醒只在发布所在的**日历周日**出现，周一 00:00 消失。这与学习日 04:00 的统计边界是两个不同用途的时间规则。

### 3.3 时区与缺失记录

按记录已经保存的 `reviewed_on` 判断学习日，不能在换时区后用当前时区重新分配历史日期。快照保存生成时采用的时区和窗口版本。

`reviewed_at` 是绝对时间戳，单独一个时间戳不能还原用户作答时所在时区。因此“原始本地小时已经齐备”的结论过强。首发若不新增每条记录的时区字段，时段关键词按快照生成时区计算，定位为近似描述；已知时区发生切换的窗口停用该类关键词。无法知道的历史旅行时区不能假装精确还原。

缺失作答时刻时，只跳过时段分析，仍可用学习日统计次数与天数。不因为“暂无老用户”取消导入、缺字段、旧客户端兼容。

## 4. 生成、归档与历史

建议默认：完整窗口内有至少一条有效正向词汇作答即可生成。0 条不生成更新内容；1–5 个学习日可以有较短周报。这是产品假设，后续按真实使用体验校准，不声称已证明能提升留存。

如果继续保留原定 ≥6 天门槛，技术上也可以实施，但文案和目标应承认它服务于高频学习用户；不能继续声称已经解决轻度用户的激励问题。提醒门槛与生成门槛应分别定义，不能因不通知就不给用户主动查看。

| 状态 | 用户看到什么 | 数据行为 |
|---|---|---|
| 周期尚未结束 | 不发布半周周报 | 可内部计算，不产生提醒 |
| 周期结束，数据可用 | 有可主动打开的回顾 | 生成并可靠保存快照 |
| 周期结束，无本功能范围内记录 | 没有更新提醒 | 不造空白六页、不显示未达标 |
| 周一以后第一次打开 | 可以从历史入口阅读 | 补算可恢复的窗口，不补发过期提醒 |
| 有历史，最近一周无回顾 | 历史入口仍可用 | 不以“本周不达标”封锁已有历史 |
| 内容生成或保存失败 | 学习照常；主动查看时有简短重试提示 | 不把失败当作无记录，不发送“已准备好”通知 |

“保质期”只作用于顶部宣传与外部提醒，**不等于删除周报或让入口失效**。历史列表只列已有周报，跨过无内容周，不制造空楼层。

用户已经看过的历史不因今天继续学习、随机抽取或普通文案升级而悄悄变化。跨设备补到旧记录时，允许以明确的“已补入其他设备记录”说明更新版本；保留更新前版本用于恢复，避免把数据修正伪装成从未改变。客户端和云端的具体冲突规则见配套规划。

## 5. 页面内容与降级

完整周报最多六页；最短三页为封面、真实学习事实、累计或结束页。不能要求轻度用户为了看一个数字翻完五次。

| 页 | 展示条件与内容 | 数据不足时 |
|---|---|---|
| P1 封面 | 日期范围 + 一个有证据的关键词 | 无适合关键词时显示“这一周的日语时光” |
| P2 投入 | 有作答的学习日数；有效学习时长可用时展示 | 有作答但计时缺失就省略时长；不足一分钟可写“不足 1 分钟”，不四舍五入成 0 后贬低用户 |
| P3 接触与巩固 | 首次正向作答词数；后续正向作答次数 | 没有新词时改以复习事实为主，或与 P2 合并 |
| P4 一个片段 | 一个具体日期与可验证事实；避开 P1/P2/P3 已突出表达的维度 | 没有独立材料就省略，不把“五次作答”自动称作“攻克” |
| P5 再见一面 | 1–8 个本周确有 fuzzy/forgot 记录的词，提供自愿复习 | 不满 5 个不凑数；没有候选就省略 |
| P6 留下的记录 | 截至这周末的累计词汇学习日、累计首次作答词数 | 旧历史无法还原时省略不可靠累计，使用中性结束语 |

可直接采用的文案方向：

- “9 月 6 日—9 月 12 日，你有 3 天与日语见面。”
- “这周第一次练习了 27 个词。”
- “这些词在这周与你见过几次。愿意的话，再见一面。”
- “截至这一周，你已经留下 128 个词汇学习日的记录。”

### P4 的首发选题顺序

1. 截至周末的连续词汇学习日刷新个人历史纪录，且这个维度未被占用。
2. 本周作答最多的一天，展示日期和实际次数；不额外声称“这个月最猛”，除非真的比较了该月。
3. 本周有效学习时长最多的一天；时长口径不能支持精确比较时不用。
4. 均不适用则省略。

“目标日期提前”“攻克反复出错词”属于后续扩展：前者需要可信预测，后者需要截至当周的前后状态证据。当前 FSRS 状态不能直接代表过去周末状态。

### P5 的选词与点击效果

- 候选仅来自当周有效正向作答，按 fuzzy/forgot 次数降序；并列按最近一次对应作答时间、稳定词标识确定顺序。
- 历史快照保存当时的展示文字与稳定词标识；打开旧周报不能按当前 `fsrs_lapses` 重新选出一批词。
- 点击按钮时重新检查词是否还存在、是否可学习；已删除词保留历史文字，但不加入队列。
- 复用现有明确的加入复习入口，重复点击不能重复入队，不增加每日新词配额、不重置 FSRS、不打断当前学习场次。若现有入口做不到，先提供“查看这些词”，再完成专门的接入验收。
- 加入成功与失败反馈必须真实；取消操作不改任何学习数据。

现有 `addWordsToQueue()` 服务于**未学新词**，已学词会返回 `alreadyLearning`，因此不能直接拿来实现 P5 的“这些旧词现在再练一次”。`addWordToTodayEncore()` 也受当日到期条件限制，并会改学习阶段。应核对既有自选复习入口，明确是安排之后复习还是另开自选练习，按钮文字和实际行为必须一致。

## 6. 关键词与参照物

保留“只从实际命中候选中选择”的机制。同一快照保存最终关键词、参照物类别、文字和规则版本，不能只保存随机种子后每次重算。

首发可以用固定等权或有限人工权重；它们是**设计权重**，不能称为已测得的稀有度。命中率、候选内选中率和最终采用率分别统计，采用率低不自动说明阈值过严，更不要求每个词必须达到 3%。

建议沿用已有关键词，但纠正解释：

- “夜行者”取 22:00–04:00，“早起鸟”取 04:00–08:00；并列最高时不靠对象遍历顺序强行选中一个时段。
- “通勤党”只能说明时间相似，不能证明在通勤；建议改称“晨昏相伴”。
- “匀速前进”应基于七天明确的作答分布；不能丢掉零新词日后称整周平稳。
- “攻坚手”不能只靠某词作答 ≥5 次就推断突破。首发可改称“常来常往”，直接对应重复接触。
- “铁人”等人格化标签不应承诺每周不同；相同真实习惯连续命中是正常情况。

参照物首发使用真实复习量、真实连续天数，以及按固定长度的轻量时间换算。45 分钟是一种展示约定，宜写“按每集 45 分钟，约相当于……”，不暗示真实看过某节目。不足换算下限就不显示。

全篇统一去重：P2 已用时间换算，P3 不再使用；P1 已突出坚持，P4 不再重复。最多两条参照，不足时不凑。

## 7. 预测与对标：首发停用，后续有条件加入

“40000 词 ÷ 18 年”是把某个累计存量平均摊到年龄，不能推出“日本大学生的平均词汇增长速度”。“3500 词 ÷ 3 学年”也至多是课程量的摊分，不能直接称为学生真实学习速度。即便这些累计数字有来源，也仍需证明统计对象、词的计数单位、起点和观察区间可比。

N1/N2 等级不能靠累计接触任意 10000/6000 个词判定。JLPT 官方说明不再发布固定的词汇、汉字和语法项目清单，考查的也包括实际运用能力。因此只能使用“本应用所选 N2 词库的学习进度”等受限表述。[JLPT 官方 FAQ](https://www.jlpt.jp/e/faq/)

如后续加入预测，规则应同时满足：

1. 针对一个明确的所选词库和内容版本，计算该词库中尚未首次作答的词，不能用全库累计直接减等级阈值。
2. 使用最近四个已结束观察周；账号开始使用前的周不充当零学习周，开始使用后的真实零新增周必须保留。首个不完整周的处理要固定并测试。
3. 速度为零、历史不完整、可用观察窗口不足时不展示预测。
4. 使用“按最近的节奏，预计在……前后完成首次练习”，优先显示月份或区间，不能把数学精度当作预测可信度。
5. 预测允许随新数据改变；不愿显示后移时可省略本期预测，但不能继续展示旧日期并称为“按当前速度”。
6. 历史最好记录若保留，必须命名为历史记录；目标、词库或规则改变后不能拿同一个 `best_eta` 混比。

## 8. 入口、手势、动效与可访问性

保留“二楼”作为空间概念：主页顶部下拉是快捷入口；同时提供安静、可点击的“学习回顾”入口。下拉只在主页滚动到顶部时开始，不绑定学习答题页。

| 操作 | 首发约定 |
|---|---|
| 进入 | 下拉或点击入口；键盘可聚焦激活 |
| 退出 | 始终可见的关闭按钮、Escape、页面返回；退出恢复原焦点与位置 |
| 翻页 | 横向滑动 + 上一页/下一页按钮，支持键盘 |
| 切周 | 日期列表直接选择；垂直翻层在第二阶段补充 |
| 长内容 | 允许普通纵向滚动，不能因为翻层手势把内容截断 |
| 斜滑、点词、选字 | 明确方向锁定和可交互区域优先级；一次手势只执行一个动作 |

“换方向、换区域”能减少冲突，却不能证明零歧义。垂直切周应限于专用区域，或仅在内容滚动边界启用；实现前在小屏、放大文字和 iOS WebView 实测。顶部 15% 只是草图比例，不能作为所有屏幕的硬编码触控边界。

现代 CSS 视觉和统一紫色系保留；单页一个视觉重点。首先用现有 CSS、组件和动效能力，不预先引入五套动效库。

动效默认值建议为：用户开关默认开，但只有在系统未要求减弱动态效果时才启用高级动效。两者优先级为 **系统要求减弱 → 关闭高级动效；用户手动关闭 → 同样关闭**。系统设置变化应即时生效；简单的非位移淡入可保留，但粒子、翻转、滚动数字和震动不得阻挡正文读取。应用转后台、离开周报或切换页面时停止无用动画。

验收覆盖 VoiceOver、键盘、焦点恢复、文字放大、对比度和触控目标；不能只用一个开关代替可访问性。数字动画要保留可直接读取的最终值。

## 9. 通知与安静提醒

现有项目使用 Capacitor **本地通知**。插件支持按星期安排通知，不等于应用关闭时能自动读取最新数据库、判断本周资格并生成内容。[Capacitor 6 本地通知文档](https://capacitorjs.com/docs/v6/apis/local-notifications)

建议首发仅承诺站内更新提醒。第二阶段的本地通知规则：

- 用户自愿开启周报通知；拒绝权限不影响阅读，不反复申请权限。
- 只在周期已结束、周报保存成功、尚未过周日 16:00 时，安排这一份报告的一次性通知。
- 不设置无条件每周重复通知，不给无报告的人发送“周报已准备好”。
- 16:00 之后首次生成，不补发过去时刻的外部提醒。
- 每份报告在单设备上去重；内容被删除、退出账号、开关关闭时取消相应待发送通知。ID 必须避开现有学习、成就、测试和备考提醒。
- 点通知先等待账户与本地库就绪，再跳到指定周；已删除或不可恢复时返回历史列表并说明状态。
- 多设备推送去重若未实现，只承诺单设备去重；正式启用前选择一个通知设备，或者补充服务端协调，不能声称离线条件下全局恰好一次。

若要求“用户整个周末不打开应用，仍保证周日按最新数据发通知”，应单列远程通知与后台数据可用性项目；不能计作现有本地通知模块的一点文案改动。平台送达时间也不应写成硬保证。

顶部提醒：每份新报告至多一次明显但短暂的提示；之后为静态轻提示，阅读后消失，周一 00:00 无条件消失。不在答题中播放、不补播过期动画。

## 10. 本地历史、云端权益与分享

建议权益边界如下，属于对原稿的明确调整：

| 能力 | 免费 | Pro |
|---|---|---|
| 最新完整周报 | 可读 | 可读 |
| 已在本机保存的历史 | 可读，不因日期变老重新上锁 | 可读 |
| 本地备份中恢复的已有周报 | 可读 | 可读 |
| 云端历史归档与跨设备恢复 | 不作为免费承诺 | 提供，先完成同步和删号验收 |
| 订阅到期后的本地历史 | 不删除、不锁回 | 同左 |

免费与付费差异体现在云服务。若仍选择“本地旧周也付费”，需另行明确免费几周、到期后的已读内容、离线权益和已购用户规则；原稿“很久以前”不能直接进入开发。

首发不使用“永久保存”承诺。建议云端至少提供明确的保存期限；具体期限在云服务上线前填写，并写清订阅到期、重新订阅、删号和导出处理。期限未定不售卖该项能力。

分享基于**已经展示的同一快照**生成，先预览再由用户分享。默认不带账号、邮箱、通知标识和 P5 易错词详情。用户取消分享不记为分享成功；系统分享面板完成也不代表第三方已发布。长图应包含统计日期，隐藏缺失模块，覆盖中文、日文和长词排版；生成失败不影响周报和学习数据。

## 11. 如何判断有效

- 主目标：以预先定义的 eligible 用户为分母，比较下一周是否有有效学习记录。例：发布后接下来的完整统计周至少一次有效学习，为“次周返回”。
- 必须同时看原本每周学 1–2 天、3–5 天、6–7 天的群体，避免只对高频用户有效却称为轻度用户产品。
- 诊断指标：有内容覆盖率、入口可发现性、打开与读完、主动加入复习后实际开始学习、渲染失败、重复提醒。
- 护栏：学习页错误、数据保存失败、周报加载卡顿、退出困难、通知关闭和动效关闭反馈。
- 不直接比较“看周报的人”和“不看的人”推导因果；愿意看的人本来可能更活跃。有足够样本再对同一资格人群随机分组；样本不足时报告描述性结果和访谈。
- 原稿模拟结论只适用于那些模拟输入；“最高占比 <40%”“无死词”等不能作为真实用户分布保证。保留模拟脚本、种子、输入和结果，才便于复核。

首次上线不需要为此搭一套通用分析平台。先确定事件、分母、版本和去重方式；如果现有隐私说明不覆盖所需采集，先用本地诊断及自愿反馈，不能默认上传词条、答案或完整报告。

## 13. 技术复查对产品承诺的进一步限制

配套开发规划第 12 节记录了新增技术证据，下列约束应与前面的建议一起采用：

- **“数据齐备”需要跨端验证。** 小程序目前既不写入 `reviewed_at`，也未在已识别的 reviews 表中保留这个未知列。真实导入/导出隔离复现确认了字段丢失；修复前不能向跨端用户保证完整时段标签。
- **“练习次数”需处理事件来源。** 现有一键完成也写普通正向作答事件，不能据此推断用户逐题练习、深夜集中学习或发生学习量高光。决定有效事件范围后，必要时补最小来源字段；旧数据无法可靠区分时减少推断。
- **正向次数与时长不是相同覆盖范围。** 现有日时长混合了 WordStudy 计时器覆盖的不同模式，没有方向维度；首发无法明确解释时就省略时长，而不是写成“这次正向练习用了多少时间”。
- **跨 04:00 秒数尚有结算边界误差。** 日总时长按结算时刻归日，不能只靠周报查询实现严格分秒分周。当前累计时长适合有限精度的回顾，不应声称历史秒数完全准确。
- **二楼不能产生学习记录。** 若未来采用覆盖当前会话的容器，必须暂停底层计时、读音和快捷键，关闭时恢复；主页入口优先。

这些是对首发能力与数据含义的限制，不代表本次已经修改采集、同步或通知实现。

## 14. 已采用的最终产品口径（2026-09-12）

本节是产品负责人后续拍板的实现依据，优先于前文中的建议方案和待决策表。前文保留，用于说明为什么曾提出更保守的范围及其技术风险。

| 项目 | 已采用规则 |
|---|---|
| 生成资格 | 一个完整周期内有任意有效学习记录或有效学习时长即生成；学习 1–5 天同样可看 |
| 内容范围 | 所有真实学习模式；批量完成与手动熟知不算逐题学习 |
| 周期 | 上周日 14:00（含）至本周日 14:00（不含） |
| 发布与提醒 | 周日 14:00 形成最终快照，14:30 一次性本地通知；没有记录则不通知 |
| 免费范围 | 只展示最新一期成品；更早原始学习数据保留 |
| Pro 范围 | 本机历史成品、云端归档与跨设备恢复 |
| 预测 | 首发不做效率档位、“提前几周”或无明确基准的 ETA |
| 学习中点通知 | 点击后离开学习页并进入周报；退出直接回主页 |
| 周报计时 | 周报页面不属于学习页，不累计学习时间 |

内容按实际材料自适应为 4–6 页：封面、投入、接触、可选高光、可选“再见一面”、结束。事实不足就省略可选页，不凑页数。分享图片使用同一份已保存快照；疑难词复习必须由用户点击，打开指定词练习，不在阅读周报时改动 FSRS。
