# 每周复习周报（"二楼"）开发规划

> **本文是落地规划**，讲"怎么建、先建什么、怎么验收"。
> 产品与交互的完整规格（文案、档位、关键词池、动效清单）见 [`WEEKLY_REPORT_DESIGN.md`](./WEEKLY_REPORT_DESIGN.md)。
> 当前状态：设计已定稿，数据层已实现，其余待开工。

---

## 一、做什么

给 App 加一个**每周复习周报**：

用户一周内有超过 5 天学习记录时，周日会收到一条推送；从主页顶部下拉可以进入一个独立的沉浸式空间（"二楼"），看到这一周的复习总结。往上一层可以翻到上一周、上上周。

**定位是情绪产品，不是数据分析页。** 目标用户是"兼职学一学"的轻量用户，核心指标是**留存**，不是功能使用率。

### 三条不可动摇的原则

| 原则 | 含义 |
|---|---|
| **零负反馈** | 文案里不出现任何可能被读成"你不行"的表述。不达标就什么都不发生 |
| **只夸不贬** | 只呈现绝对值、累计值、高位比例；不出现"少 / 只 / 仅 / 才" |
| **门槛不可见** | 不做"差一天解锁"这类提示。用户视角只有两态：收到周报 / 什么都没发生 |

这三条是验收时的**否决项**——任何一条被违反，功能不算完成。

## 二、前置结论（已核实，无需重新调研）

| 项 | 结论 |
|---|---|
| **数据是否齐备** | ✅ **齐备，不需要新增任何采集字段**。时段类关键词所需的答题时刻，`reviews.reviewed_at`（写入值为 `Date.now()`）已经在写 |
| **云端成本** | ✅ **可忽略**。快照存 R2，100 万用户存满三年约 23 GB，约 $0.35/月 |
| **现有代码** | ✅ 项目里**没有任何周报相关代码**，是干净的白纸 |
| **老用户兼容** | ✅ 产品尚无老用户，`reviewed_at` 从第一个用户第一天起就有值 |

## 三、必须先处理的三个口径坑

实现前必读，否则会踩：

**坑 1 · `studyDate()` 有"凌晨 4 点算前一天"规则**

`frontend/src/lib/database/db-utils.ts` 里的 `studyDate()` 会把 00:00–03:59 的记录归到前一天。
→ **处理**：时段类关键词必须读 `reviewed_at` 的**原始本地小时**，不经过 `studyDate`；且「夜行者」的区间是 **22:00–04:00**，不是"22:00 后"。

**坑 2 · `reviews.direction` 不是"新词 / 复习"**

它的值是 `forward` / `reverse`（正反向答题），和"这个词是不是第一次见"无关。
→ **处理**：用子查询判断该 `word_id` 在 `reviews` 中的**最早 `reviewed_on` 是否落在本周**。

**坑 3 · 已作废** —— 原担心老用户 `reviewed_at` 为空，产品无老用户，不存在。

## 四、实现阶段

工作量用相对值标注（S / M / L / XL），便于排期，不代表绝对工时。
**关键路径**：阶段 1 → 2 → 3 → 4，其余可并行。

### 阶段 1 · 数据层 ✅ 已完成

**交付物**：`frontend/src/lib/analytics/weekly.ts` + `weekly.test.ts`

纯读函数，不写任何表。包含：自然周窗口、周指标（天数/时长/新词/复习/每日分布/连续天数/累计）、10 个关键词判定、加权随机选取、速度档位、目标日期、参照物池组装。

**验收**：30 个单元测试全过；`npm run check` 干净；全量测试无回归。 ✅ 已通过

---

### 阶段 2 · 存储与同步 —— 工作量 M

**交付物**

- 本地 `weekly_reports` 表（缓存 + 免费用户的历史）
- 云端：**内容存 R2**（key = `weekly/{user_id}/{week_start}.json`），**索引存 D1**（只存 `user_id + week_start`）
- `best_eta` 持久化（放已有的 `app_state` 通用 KV）

**关键约束**

- ⚠️ **内容必须存 R2，不能存 D1** —— R2 $0.18/GB·年，D1 $9/GB·年，差 50 倍
- ⚠️ **索引只对付费用户写** —— 否则 100 万用户三年吃掉约 1.6 GB D1 存储，而 D1 免费额度只有 5 GB
- ⚠️ 复用或绕开现有 `SYNC_PUSH_LIMITER`（2 次/60 秒），否则同步会莫名失败

**验收**：本地建表迁移幂等；云端迁移可重复执行；断网时全流程不受影响。

---

### 阶段 3 · 二楼容器 —— 工作量 L

**交付物**：二楼组件（下拉展开、手势分区、楼层牌、周次刻度）

**手势表（一个方向一个语义，零歧义）**

| 手势 | 区域 | 含义 |
|---|---|---|
| 上拉 | 顶部 15% 区域 | 回主页 |
| 垂直滑 | 内容区 | 翻层（切换周） |
| 水平滑 | 卡片区 | 翻页（周报内部详情） |
| — | 画布留白区 | 手势死区，不响应 |

**验收**：四个手势互不干扰；楼层牌在每层顶部可见；可翻到任意历史周；能顺利退出。

---

### 阶段 4 · 内容与动效 —— 工作量 XL

**交付物**：6 页内容组件 + 动效

| 页 | 内容 |
|---|---|
| P1 封面 | 本周关键词 + 周次日期 |
| P2 投入 | 有数据的天数 + 时长 + 时间换算 |
| P3 收获 | 本周新词数 + 参照物 1–2 条 |
| P4 高光 | 本周最亮的一刻（动态选主角） |
| P5 该处理的 | 5–8 个词 + 一键加入复习 |
| P6 累计 | 累计天数 + 累计学过词数 |

**视觉**：现代网页风，**零图像素材**（底色、细线、圆角、字号、间距全部 CSS）。亮深紫色调，与主页视觉独立。

**动效**：默认全开，可拉到"令人厌烦"的程度。

**验收**：每页 1–2 个信息点；全篇翻 4–6 次；视觉与主页有明显区隔。

---

### 阶段 5 · 设置项 —— 工作量 S

**交付物**：设置页新增"高级特效"开关（两态：开 / 关）

**约束**：必须**自动联动 iOS 系统"减弱动态效果"**（`matchMedia('(prefers-reduced-motion: reduce)')`）。这是可访问性硬要求，前庭功能障碍者看多了会真的眩晕。

**验收**：系统开关打开时自动降档；用户手动关闭后动效确实消失。

---

### 阶段 6 · 触达 —— 工作量 M

**交付物**：推送通知（周日下午）+ 更新日主页顶部动画提醒

**约束**

- 推送只做钩子，文案短、不承载内容
- 顶部提醒**第一次重、之后轻**；**只在更新日出现，次日必须恢复安静**
- 不做未读红点、不做任何催看机制
- 二楼有保质期，过期静默归档，不提示"你错过了"

**验收**：连续两周观察，非更新日顶部无任何提示。

---

### 阶段 7 · 分享长图 —— 工作量 M

**交付物**：canvas 本地生成可分享的长图

纯前端，无数据依赖。可与其他阶段并行。

---

### 阶段 8 · 付费墙 —— 工作量 S

**交付物**：历史周报的付费边界（复用 `lib/entitlements.ts`）

**约束**：**付费墙只能挡在"看很久以前的周报"上，绝不能挡在"看本周周报"上。** 免费用户看本周永远免费。

**验收**：免费账号点开本周周报无任何付费提示。

## 五、上线后需要校准的参数

**这些不能凭直觉定，必须用真实数据回填。** 目前的数值来自模拟，模拟只能验证机制，不能验证参数。

| 参数 | 现状 | 校准依据 |
|---|---|---|
| **速度档位线** | 22 / 43 / 64 / 100 词/周 | 真实用户的**日均新词量**。临界点在 10 附近——若中位数 > 10，档位线需整体上调 |
| **关键词稀有度** | 人工预设 2–5 | 上线后统计真实命中频率，替换预设值 |
| **关键词判定阈值** | 如「单日爆发」3 倍日均 | 监控采用率，任何低于 3% 的关键词要检查判定条件是否过严 |
| 时间换算下限 | 45 分钟 | 观察轻度用户是否因不启用而缺少参照物 |

**已可放心直接实现的**（模拟四组情景下均稳健）：无死词、关键词最高占比 < 40%、P4 不重复夸同一件事、不适用比例 < 30%。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 二楼"交互隐藏太深、打开率低"（淘宝二楼的已知缺陷） | 已设计"更新日顶部动画提醒"作为发现路径；只做一层入口，不叠加多层 |
| 多层结构超出已验证模式，用户迷路 | 楼层牌（日期标识）必须做重；提供周次刻度直达 |
| 门槛筛掉的恰好是最需要激励的轻度用户 | 门槛只决定"有没有周报"，不决定"周报好不好看"；达标用户看到的永远是正向内容 |
| 动效拉满导致用户反感 | 两态开关 + 系统联动；非更新日顶部完全静止 |
| 云端成本随用户增长 | 内容存 R2、索引只对付费用户写；成本与付费收入直接挂钩 |

## 七、验收总清单

- [ ] 三条原则无违反（零负反馈 / 只夸不贬 / 门槛不可见）
- [ ] 一周 ≤ 5 天有数据时，全流程无任何提示
- [ ] 二楼四个手势互不干扰
- [ ] 可翻到任意历史周，且能顺利退出
- [ ] 免费账号看本周周报无付费提示
- [ ] 系统"减弱动态效果"打开时动效自动降档
- [ ] 非更新日顶部无任何提醒
- [ ] 全流程离线可用（不依赖云端）
- [ ] 文案中不出现"少 / 只 / 仅 / 才 / 差"
- [ ] 时间换算不出现"0 集日剧"
