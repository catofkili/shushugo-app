# JLPT 刷题（实验功能）规格

> 2026-10-02 立项。作者原话：「我要做一个 jlpt 刷题功能」。目前是**实验功能**，题库只有试做批，
> 和开口练习一样不许进任何发布包（作者 2026-09-30 定的规则：「不要把断头工作上传到要发布的小程序 / App 上」）。

## 0. ⚠️ 发布闸门（照开口练习那套，开关单独一个）

唯一开关是编译期常量 **`__EXP_JLPT__`**：vite dev / vitest 为 true；`vite build`（网页、iOS）和 `taro build` 默认 false，
只有 `SHUSHUGO_EXP_JLPT=1` 才打开（只用来自测或出小程序预览码，**带这个开关构建的包永远不许上传**）。

- ⚠️ **不和 `__EXP_TALK__` 共用一个开关**：开口练习上线那天会去掉它自己的开关和拦截，刷题要是挂在同一个开关上，就会被一起带上线。
- `lib/jlpt-practice/` 只许被这几处引用：`routes/jlpt-practice.tsx`、`pages/JlptPracticePage.tsx` 和 `features/jlpt-practice/`、
  小程序 `taro-spike-2/src/study/jlpt-practice/`。别的模块一 import，开关关着也摇不掉。`isolation.test.ts` 钉着这条。
  入口按钮（备考计划页）只做 `navigate("jlpt-practice")`，不 import 这个目录。
- 拦截：`taro-spike-2` 的 `check:release` 拦 app.json 里的 `jlpt-practice` 页面和产物里的 `__SHUSHUGO_EXP_JLPT__` 指纹；
  `scripts/build-ios.sh` 见到 `SHUSHUGO_EXP_JLPT` 就退出，构建完再搜一遍指纹。
- ⚠️ **作答表 `jlpt_answers` 是 `cloud: false`**，理由和 `talk_*` 一样：`assertSnapshotWritable` 见到不认识的表会整次拒绝同步。
  作者的 5173 开发版打开了这个功能，只要把这张表推上云，作者手机上的已发布版本就再也同步不了。
  上线时先发「认得这张表、仍是 false」的版本给所有端，全部更新之后再改成上云。

## 1. 题从哪来

- **真题不能用。** 新 JLPT（2010 年起）官方不公开真题，只出过两本《公式問題集》；北京日本文化中心声明试题版权归
  国际交流基金和日本国际教育支援协会，除官网公开的问题例外，不允许任何个人或组织使用。市面上 2010 年以后的「历年真题」
  多半是考生回忆版或流出卷，没查到授权记录。旧 JLPT（1984–2009）的真题有正版（外研社、学林出版社），但授权只覆盖那本书，
  题型也和现在不同。
- **题目全部原创，Codex 手写、另一个 Codex 会话盲做审校、Claude 验收。** 规则和调度脚本在
  [`jlpt-authoring/`](jlpt-authoring/README.md)（出题 `rules.md`、审校 `review.md`、`run-job.sh`、`gen-set3.sh`）；
  实际干活的目录是 `~/Documents/shushugo-wt/_codex/jlpt-trial/`，题稿和 Codex 日志在那里，不进仓库。
  作者手里有一本红蓝宝书 N3 1000 题，**只给 Claude 看来总结题型和干扰项的套路**，原题一道都不给 Codex，
  出题素材只有我们自己的词表和语法表——和语法说明重写那次「不读原书」同一个口径。
- 试过用脚本从词库自动出题（2026-10-02）：漢字読み、表記这两类机械变形还可以，言い換え、文法两类的干扰项经常读不通，
  作者也定了「不要脚本，手写」。别再回到自动出题。

## 2. 题库格式

类型定义在 `frontend/src/lib/jlpt-practice/types.ts`（数据层、界面、导入脚本共用的约定）。每级一个文件
`frontend/src/data/jlpt/n1.json` … `n5.json`，由导入脚本从审完的题生成，由校验脚本把关。

- 题的 id 稳定（`n3-v-trial1-07`），作答记录按 id 记。内容修订不换 id，整题换掉才换。
- 一套卷 = 同一个 `setId` 的全部题（文字・語彙 + 文法）。以后加卷就是加一个 set。
- 题量照 JLPT 各级的大题结构（官方 2020 年后不再公布小题数，按通行题数）：

| 等级 | 文字・語彙 | 文法 |
|---|---|---|
| N5 | 漢字読み 7 / 表記 5 / 文脈規定 6 / 言い換え類義 3 | 文法形式 9 / 組み立て 4 / 文章の文法 4 |
| N4 | 7 / 5 / 8 / 4 / 用法 4 | 13 / 4 / 4 |
| N3 | 8 / 6 / 11 / 5 / 5 | 13 / 5 / 5 |
| N2 | 漢字読み 5 / 表記 5 / 語形成 3 / 文脈規定 7 / 言い換え類義 5 / 用法 5 | 12 / 5 / 5 |
| N1 | 漢字読み 6 / 文脈規定 7 / 言い換え類義 6 / 用法 6（没有表記） | 10 / 5 / 4 |

- 读解和听解这一期不做（要原创文章和音频，成本高一个量级）。
- ⚠️ **小程序里题库单独一个 `jlpt-bank` 分包**（`bank.ts` 的 webpackChunkName `jlpt-bank/jlpt-nX` + `app.config.js` 只在开关开着时登记，
  进刷题页预下载）。2026-10-06 两套卷 482 题占 561 KB，每题约 1.16 KB，单个分包上限 2 MB，还能放约 1,300 题（五套多）。
  原来放在 `lazy` 分包里，可 lazy 还装着各 tab 的界面代码（tabs.js 已经 989 KB），第四套卷就会顶到 2 MB、整个小程序传不上去。
  再往上加卷之前看 `reports/package-sizes.json` 里 `jlpt-bank` 那一项（开关开着构建才有）；要分就按等级拆成两个分包。

## 3. 三种练法

| 模式 | 出题 | 反馈 | 记录 |
|---|---|---|---|
| 按题型练 | 选等级 + 题型，一组 10 题：先没答过的，再错题，再最久没答的 | 每题答完当场给对错、解析、选错那项为什么错 | 每答一题记一次 |
| 模拟卷 | 选一套，先文字・語彙再文法，计时（建议 1 分钟一题），到时自动交这一部分 | 交卷后才给 | 交卷时整批记；中途退出不记 |
| 错题本 | 最近一次答错或没答的题 | 同按题型练 | 同按题型练 |

- **不写 FSRS，不进今日计划。** 四选一能蒙对，答对一题不能说明记住了这个词（和辨析气泡不放评分按钮同一个理由）。
- **不出「预计 xx 分 / 能不能过」。** JLPT 的分项分数是等化后的标准分，复刻不了；只给各大题正确率。
- 等级默认取备考目标 `jlptTarget`，可以切换。

## 4. 作答记录

`jlpt_answers`（append，`cloud: false`）：每答一题一行，记 question_id、level、kind、chosen（0 = 没答）、correct、
mode、session_id、学习日、时间。错题本、统计全从这张表现算，不另存计数器。
照例三处登记：`sync/tables.ts`、`scripts/user-data-tables.mjs`、`local-schema.sql`。
