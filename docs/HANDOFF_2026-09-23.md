## 2. 怎么干活（这套构建的规矩）

```bash
cd wechat-miniprogram
node scripts/build-shared.mjs      # 改了 frontend/src/lib 之后必跑，产物要提交
npm run check-shared               # 比对产物是否和 frontend 源码一致（CI 会跑）
npm test                           # 21 个脚本，入口是 scripts/run-all.mjs（枚举 package.json）
```

- **新功能进小程序：先看能不能加进 `scripts/shared/entry.ts`。** 不能（碰 DOM、带出厂内容 JSON）
  才去 `scripts/shared/shims/` 写 shim，**shim 只做平台替换，不改判据**。
- 出厂内容数据在两个分包里，装载器 `src/shared/content.js`（`require.async`）。
  ⚠️ **顺序是硬要求**：`database-store.ensureContentLoaded()` 在库就绪前灌好，
  再点网页那几个 `loadXxx()` 的缓存。网页的 loader 是 `loading ??= import(...)`，
  **失败一次就永久失败**，之后音高重音 / 汉字卡整个不出现。
- ⚠️ 模块初始化就取一层属性的数据（`kanji_variants.japanese_to_simplified` 等）必须走
  `shims/lazy-json.js` 的**活代理**；返回 undefined 会让 `?? {}` 把空表永久固定下来。
  自他动词对相反（网页 init 时 `Object.entries()` 展开），**只能同步**，留在主包。

### 页面自检脚本（改了页面就跑一下）

会话里临时写的，没进仓库。要用就重建一个：逐个 `require` 页面模块、桩掉 `Page()`，
跑 `onLoad` / `onShow`，看 `data` 有没有拿到东西。上次结果：20 个页面全 OK。
（`wx` 的桩至少要有 `env.USER_DATA_PATH` / `getFileSystemManager` / `getStorageSync` /
`setStorageSync` / `showToast` / `navigateTo` / `createInnerAudioContext`。）

⚠️ 页面 handler **不返回 promise**（微信也不 await），所以自检脚本里要等 `data.busy` 落下来。

### 已验证的改动

1. 开发者工具第一次真正编译时，`src/shared/content.js` 的 `require.async(SOURCES[name])` 没把分包模块带进去。
   换成每个模块的静态字面量路径后，内容分包和学习页能打开。Node 测试此前未覆盖微信的编译阶段。
2. 模式页原来的 `navigator` 无法带 query 跳到 tabBar 单词页；现在选模式先存 `pendingStudyMode`，
   再 `wx.switchTab`，单词页 `onShow` 取走。共享包在微信逻辑层切页后还会遇到裸 `localStorage`
   消失、`window.dispatchEvent` 落到平台原生 EventTarget 的问题；`polyfill.js` 给共享包固定本模块的
   storage 与事件总线。模拟器已验证选「混合学习」、改每日量的偏好写入。
3. 模拟器点完语法插播时曾连续给下一张语法，违背「每 5 个单词只插一张」；页面改为清掉插播后
   回到下一张单词。空卡文案不能压在插播卡底下。自动脚本的三种卡出题、各自流水表、撤销测试通过；
   模拟器实际连答单词后看到了语法插播，答完回到单词，「上一个」恢复刚才的语法卡。
   页面撤销顺序改成和网页一样的最近两笔类型栈，避免连续撤销跨卡种；撤掉触发插播的单词后重答，
   要恢复同一种插播，`modes-smoke` 有判据。
4. `persistSoon` 和页面显式保存会争用同一个 `.tmp` 文件，模拟器出现 `rename:fail`；
   `database-store.atomicWrite` 现在串行。`runtime-smoke` 测三次并发保存以及故意损坏主库后从 prev 恢复。
   测试故意破坏文件前必须等 300ms 的后台防抖保存完成，否则测试自己会把损坏的 main 轮转成 prev。
5. 每日量页面 `/pages/daily-plan/index` 以共享 `daily-plan.ts` 为唯一计算与保存口径：四段 log 圆环、
   松手落盘、数字表单、建议补量、一键安排、备考预设、撤回。**保存传入面板渲染时的 `shownView`**，
   没动的 cap（尤其单词的 400）不变。模拟器改新学 16→17 成功落盘并重排，撤回又回到 16；
   `daily-plan-smoke` 钉住 cap 与总量撤回。圆环在模拟器能画出四段；触屏拖动手感还需真机验收。

## 10. 小程序微信身份关联已有账号（2026-09-24）

- `/api/auth/wechat` 对已关联微信身份仍照常登录；新身份现在必须显式带 `create_account: true` 才创建用户。
  未带此标记时返回 `WECHAT_ACCOUNT_NOT_FOUND`，设置页和组队入口先让用户选“新建账号”或去关联已有账号，避免一次普通登录点击就拆出第二份云账号。
- 「我的 → 已有账号？关联微信」先向用户登记邮箱发送一次性验证码，再由 `/api/auth/link-wechat` 同时核验邮件码和 `wx.login` 一次性 code；成功后在原用户下写入小程序 OpenID / UnionID 别名并返回原账号会话。此流程也支持 Apple 登录账号，因为它验证账号登记邮箱，不依赖邮箱密码登录。
- `/api/auth/request-wechat-link` 按 IP、邮箱哈希和用户限速；邮件码使用既有 `auth_email_tokens` 哈希存储、单次使用和失败次数上限。未知邮箱与已登记邮箱返回相同的成功文案，降低账号枚举风险。关联服务在发邮件前确认 Worker 的邮件服务配置。
- 如果 OpenID 或 UnionID 已归属另一个用户，服务端仍以冲突拒绝关联，不迁移身份，也不合并学习记录或权益。此变更阻止后续误建账号，并给尚未创建小程序账号的旧用户提供安全关联路径；已拆分的历史双账号仍需另定确认与合并方案。
- 小程序隐私政策增加了账号邮箱及 Resend 验证邮件的说明，版本升为 `2026-09-24`；Worker 的政策正文由 Web 内容源导入，小程序版本号同步更新。关联与新建均要求同意当前政策版本。
- Worker 必须与更新后的小程序客户端配套部署：旧客户端没有 `create_account` 确认参数，Worker 更新后遇到从未关联的新微信身份会收到 `WECHAT_ACCOUNT_NOT_FOUND`，直到用户更新小程序；建议紧接着上传新客户端。不要把 Worker 已部署说成账号关联已验收。
